## 🧭 2. Машина состояний ввода

Одно поле `Input.st`, один набор обработчиков (`pointerdown` на `#game` + `setPointerCapture`; `pointermove/up/cancel` на `#game` через захват; `wheel`, `contextmenu`, `blur`, `visibilitychange`). Кнопки читаются из маски `e.buttons` на **каждом** `pointermove` — так видны аккорды (K3).

```
                 ┌────────── Esc · ПКМ · 2-я кнопка · blur · cancel ──────────┐
                 ▼                                                            │
IDLE ─ЛКМ↓─► PRESS ─сдвиг ≥ 5px─► BOX ─ЛКМ↑─► выделить рамкой ─► IDLE        │
 │             └─ЛКМ↑ < 5px─► CLICK ─► pick → выделить / снять / счётчик кликов
 │─ПКМ↓─► CMD_PRESS ─ПКМ↑ < 8px─► приказ по intent ─► IDLE
 │                 └─сдвиг ≥ 8px─► CMD_CANCEL (резерв: строй)
 │─СКМ↓─► PAN (1:1) ─бит СКМ пропал из buttons─► INERTIA ─► IDLE
 │─B / кнопка здания─► PLACE ─ЛКМ↓─► PLACE_PRESS ─ЛКМ↑ < 16px─► поставить (Shift → PLACE)
 │                      ▲  └ ПКМ/Esc/B ─► IDLE        └─сдвиг ≥ 16px─► PLACE (не ставить)
 │                      └────────── призрак = мышь, каждый кадр ──┘
 └─2-й палец (из любого тач-состояния) ─► PINCH ─пальцев < 2─► IDLE
```

### 2.1 Переходы

| Из | Событие | Условие | В | Действие |
|---|---|---|---|---|

## 🎯 4. Зоны попадания

Прямоугольник спрайта (мировые px от точки опоры `x,y` у земли) + запас в **экранных** px (`pad / zoom`) — размер попадания на экране не зависит от зума. Одна таблица `HIT` рядом с рисовкой; `pick` берёт из неё.

| Тип | Ширина | Верх → низ | Запас 🖱️ / 👆 | Приоритет |
|---|---|---|---|---|
| 🧑 человек, 🧍 герой, 🧓 NPC | 28 | y−46 → y+4 | 6 / 14 | 1 |
| 🐕 лайка | 30 | y−24 → y+4 | 4 / 10 | 1 (рамкой — нет) |
| 🐺 волк | 56 | y−34 → y+6 | 8 / 16 | 2 |
| 🐻 медведь | 80 | y−52 → y+8 | 8 / 16 | 2 |
| 🐇 заяц | 26 | y−20 → y+4 | 10 / 18 | 2 |
| 🏗️ стройка / 🛖 постройка | `BUILDS.w` | y−`h`−20 → y+`h`/2 | 4 / 10 | 3 |
| ⚙️ обломки | спрайт 320×210 / 220×140 | по спрайту | 0 | 3 |
| 🔥 куча | 40 | y−30 → y+6 | 6 / 12 | 3 |
| 🌲 ель / берёза | 0.6·110 = 66 | y−150 → y+6 | 0 / 6 | 4 |
| 🌲 кедр | 0.6·150 = 90 | y−150 → y+6 | 0 / 6 | 4 |
| 🧊 лёд, ⬜ земля | — | — | — | 5 (фон) |

Правила `pick`: 1) меньший номер приоритета выигрывает; 2) внутри приоритета — кто рисуется ближе (больший `y`); 3) скрытые (`hidden`, внутри избы) не берутся; 4) тряска экрана не учитывается — её ≤ 8 px покрывает запас. Числа — стартовые, сверить по спрайту при внедрении одним скриншотом с наложенными прямоугольниками.

## 📐 9. Экран → мир: одна функция

| Функция | Где | Формула |
|---|---|---|
| `GFX.screenToWorld(cx, cy)` | `gfx.js` | `sx = cx − rect.left`, `sy = cy − rect.top`; `{ sx / zoom + cam.x, sy / zoom + cam.y }` |
| `GFX.worldToScreen(wx, wy)` | `gfx.js` | `{ (wx − cam.x)·zoom + rect.left, (wy − cam.y)·zoom + rect.top }` |

| Правило | Почему |
|---|---|
| Вход — `clientX/Y` (CSS px), `rect` холста кешируется на `resize` | dpr не нужен (B2) |
| Тряска не входит | визуальна, ≤ 8 px (§4) |
| «Интерфейс» `--ui` не входит | холст вне CSS `zoom`; при шаге D6 №2 (оверлеи через `rdpr × ui`) не трогать эту формулу |
| Миникарта — своя `UI.mapToWorld` | другая система координат, rect уже с CSS `zoom` (S30 ✅) |
| Удалить копии | `colony.js:450`, `ui.js:433-434`, `ui.js:470`, `gfx.js:28` (стать `screenToWorld`) |
| Тесты — только через эти две | B7 правило 🧮 |
| Инвариант | `worldToScreen(screenToWorld(p)) = p ± 0.01` при zoom 0.6 / 1 / 1.6 и ui 0.85 / 1.2 |
